## 1 · `npm run preview` no sirve la aplicacion: 404 a todo lo que Chrome pide como script

Encontrado al querer mirar las pantallas de T41 sobre la construccion real, que es lo que
T34 recomienda hacer antes de empujar («npm run preview si la sirve bajo /Hero-Quest/, que
es exactamente lo que hay que probar antes de empujar»).

QUE PASA. Con `npx vite preview --port 5199`, la pagina carga el HTML y el CSS y se queda
EN BLANCO: el modulo de JavaScript devuelve 404. No es el fichero: existe en `dist/assets/`
y `curl` desnudo lo baja con 200. Lo reproduce una sola cabecera:

    curl -o /dev/null -w "%{http_code}" URL                              -> 200
    curl -o /dev/null -w "%{http_code}" -H "Sec-Fetch-Dest: script" URL  -> 404

Vale para cualquier ruta, incluido `index.html`. O sea, `vite preview` de esta version
(vite 7.3.6) responde 404 a toda peticion que traiga `Sec-Fetch-Dest: script`, que es
justo la que manda el navegador para un `<script type="module">`. Con lo cual la pagina
publicada no se puede comprobar en local con la herramienta que el propio repositorio
recomienda.

POR QUE IMPORTA. `npm run build` sale verde y `npm run preview` arranca sin quejarse: las
dos cosas que se miran. Quien vaya a comprobar la pagina antes de empujar ve una pantalla
en blanco y lo natural es pensar que la ha roto su cambio, no el servidor de previsualizacion.
A mi me costo un rato largo: mire el `dist`, el `base`, el `curl`, y todo estaba bien.

NO ES DE T41. Lo he comprobado: 404 igual con `index.html`, que T41 no toca. Es del
servidor, no del codigo.

QUE HE HECHO EN SU LUGAR. Servir `dist/` con `python3 -m http.server`, montando `dist` en
un enlace llamado `Hero-Quest` para reproducir la base de Pages:

    mkdir sitio && ln -s "$PWD/dist" sitio/Hero-Quest
    cd sitio && python3 -m http.server 5200 --bind 127.0.0.1
    # y entonces http://127.0.0.1:5200/Hero-Quest/ se comporta como GitHub Pages

Asi si carga, y con eso he podido comprobar que el logotipo y la textura llegan con la
base correcta. **La publicacion en Pages no esta afectada**: Pages es un servidor de
ficheros estaticos y no hace esta comprobacion; el `dist` construido es correcto.

QUE HABRIA QUE MIRAR. Si es una opcion de vite que se puede desactivar, o un fallo de la
version. Merece una tarea pequenna: o se arregla, o se cambia la frase de T34 y del README
para que diga como comprobar la pagina de verdad. No la abro yo porque las tareas nuevas
las numera Juan Luis (regla 11 del tablon).
